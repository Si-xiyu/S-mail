📱 前端架构 (Vue 3 + TypeScript)

💡 前端架构特点： 使用 Pinia 进行全局状态管理，通过 useMailStore 统一管理邮件、用户和 Agent 会话数据。 API 客户端自动处理认证和错误处理。

🎯 核心组件说明：

  • useMailStore (Pinia)： 全局状态管理，包含用户、邮件、标签、Agent 会话等所有应用状态
  • ApiClient： HTTP 客户端，自动处理认证、错误处理和请求/响应拦截
  • Sidebar： 左侧导航，显示标签和分类
  • MailList： 邮件列表，支持选择、删除、搜索
  • MailDetailDrawer： 右侧抽屉，显示邮件详情
  • AgentChatPanel： AI 对话界面，支持消息发送和动作确认

🔧 后端架构 (Spring Boot + MyBatis-Plus)

💡 后端架构特点： 采用分层架构，Controller 处理请求，Service 处理业务逻辑，Mapper 处理数据访问。 AgentSessionService 是核心，负责 Agent 会话管理和与 Agent 通信。

🎯 核心组件说明：

  • AgentSessionController： REST API 控制器，处理前端请求
  • AgentSessionService： 核心业务逻辑，管理会话、消息、动作，与 Agent 通信
  • 数据实体： AgentSession (会话), AgentMessage (消息), AgentPendingAction (待确认动作)
  • Data Mappers： MyBatis-Plus 映射器，处理数据库操作
  • InternalToolService： 内部工具服务，执行邮件操作
  • DTO： 请求/响应数据传输对象

🔄 主要流程：

  • Frontend 发送请求 → AgentSessionController 接收
  • AgentSessionService 处理业务逻辑
  • 如需 AI 处理，调用 Agent (HTTP POST)
  • 保存消息和待确认动作到数据库
  • 返回 Response 给 Frontend

🤖 Agent 架构 (Python FastAPI)

💡 Agent 架构特点： 采用插件架构，通过 FastAPI 提供服务。 AgentLoop 是核心处理引擎，支持多个分析提供者（DeepSeek, RuleEngine, Mock）。 所有操作通过 BackendToolClient 与后端通信。

🎯 核心组件说明：

  • FastAPIApp： FastAPI 应用入口，提供健康检查和 Agent 聊天接口
  • AgentLoop： 核心处理引擎，接收请求、路由工具、生成响应
  • AnalysisProvider： 分析供应商接口，支持多个实现（DeepSeek, RuleEngine, Mock）
  • RuleEngine： 规则引擎，使用规则进行邮件分析
  • DeepSeekAnalysisProvider： 调用 DeepSeek API 进行分析
  • ToolRouter： 工具路由器，将消息路由到不同的工具
  • BackendToolClient： 后端工具客户端，调用后端 Internal API
  • RAGTool： RAG 检索工具（目前 Mock，后续实现向量搜索）

🔄 主要流程：

  • Backend 调用 Agent 的 /plugin/v1/agent/chat
  • AgentRoutes 处理请求，调用 AgentLoop
  • AgentLoop 路由消息，调用相应工具
  • Tool 执行操作，可能调用 BackendToolClient
  • 生成响应和待确认动作
  • 返回 ChatResponse 给 Backend

📊 邮件自动分析流程

⚙️ 分析流程详解：

  • 异步处理： 不阻塞邮件投递，后台任务异步执行
  • 多提供者支持： DeepSeek → RuleEngine → Mock 自动降级
  • 容错机制： AI 分析失败时邮件仍可正常显示
  • 结果保存： 分析结果保存在 MailAiResult 表

📊 生成的 AI 结果：

{ "summary": "邮件摘要内容...", "category": "工作/个人/营销/其他", "junkScore": 0.05, // 0-1，1 表示垃圾邮件 "priority": "HIGH/NORMAL/LOW", "riskFlags": ["钓鱼", "可疑链接"] // 安全风险 }

🎯 关键设计原则：

  • ✅ 不阻塞邮件投递 - 分析是后台异步任务
  • ✅ 优雅降级 - 提供者失败自动切换到下一个
  • ✅ 用户无感知 - 分析失败对用户无影响
  • ✅ 配置驱动 - 提供者在 Config 中配置，无需改代码
